# 14.4.8 — bounded forecasts and fresh provisional formation

Correct computeV99Posterior's clock contract: clockSeconds already means seconds
remaining. Previously it was subtracted from the window length again, so scoring
used elapsed time as the remaining projection horizon. Forecasts now end at the
current 5m/15m settlement boundary. Fractional forecast bars allow the existing
FGT calculation to use a stable historical slope lookback of at least five bars
while projecting only through that short horizon. Integer horizons of five or
more bars retain their original calculation. No signal or lock threshold changed.

Unavailable/insufficient forecasts and valid neutral/conflicting forecasts have
different blocker codes and structured availability metadata. Partial inputs
are not called mixed. The existing FGT minimum and high-conviction/fast-track
exceptions remain; this does not waive a signal-quality rejection.

Before commitment, a qualifying opposite candidate may re-form with fresh
samples. All progress from the old provisional direction is discarded. After
commitment, the snapshot guard and originalDecision keep the Call immutable.
This removes stale-claim starvation without borrowing confirmation or using an
opposite candidate's score for an old direction.

Timing approval is explicitly not a lock. A bounded per-window decision trace
records the approval and downstream sample, signal, adverse-price/cooldown,
quote/commit, tape-release or frozen-feed holds. Repeated timing/sample branches
are aggregated with first/latest timestamps, counts and peak confidence to avoid
filling local caches with tick-level telemetry. At most16 groups are retained;
omitted groups are counted explicitly. It is not a full tick replay. Both
canonical record builders and original capture preserve this evidence, and the
existing sync projection/signatures and slim restore keep it. Existing records
are not retroactively rewritten with new traces or inferred reasons.

Tests execute the actual scoring engine with transitive pure helpers, actual
candidate/postprocessors, complete lifecycle, shared seal and record builders.
They cover early/mid/cutoff/end forecast contracts, fractional horizons, missing
versus neutral inputs, both directions reaching a Call, fresh reformation,
alternating candidates, locked-call immutability, explicit trend-at-lock rejection,
bounded tracing, local/cloud projections and original capture preservation.
All tests must pass and the production build must succeed before shipping.

Keep the420s cutoff,65 early/mid and62 existing late/5m confidence thresholds,
sample/tier requirements,44–77c Call band, abort/cooldown controls, AutoTrade
entry/order/exit/settings code and execution pause unchanged. No test engine,
orders, production record edits or schema migration is used for validation.

The previously reported refresh/shared-decision restoration problem is separate
and not claimed repaired by this scoped release. Running browser tabs do not
hot-swap the release; refresh is user-controlled.

Rollback by reverting this release if horizons extend past close, old-direction
samples carry into a new candidate, committed originals change, invalid/late
Calls seal, evidence persistence fails or rendering breaks. Preserve execution
pause and thresholds during rollback. Successful tests are not evidence of
profitability or a guaranteed lock in every window.
