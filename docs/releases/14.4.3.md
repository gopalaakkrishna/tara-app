# 14.4.3 — Startup readiness, blocker evidence and captured-market settlement

The live October 12 audit found zero formation samples because the cold-start
flag imposed a default 75-minute hold. Meanwhile the header read the cache
generated during that same session and reported WARM. Deadline records dropped
the warm-up reason and retained only the seven-minute cutoff message.

Startup eligibility now requires validated, recent, continuous candle history
for the active asset and source, 50 distinct real spot receipts covering at least
60 seconds, and a completed signal-engine calculation. Repeated renders,
synthetic ticks, old candles and source changes cannot satisfy this check.
Observation gaps restart sampling. A same-source refresh can reuse recent
observations from this tab. Explicit positive startup-hold preferences remain
additional holds; the default no longer delays for 75 minutes.

The header and Call formation use the same readiness object. The overview shows
the actual current blocker, and deadline records retain structured blocker
evidence, quote status and sample progress through all compact caches and cloud
merges. The seven-minute cutoff, existing captured decisions, manual overrides
and the live AutoTrade pause remain in effect.

Pending Calls with captured market tickers now query that exact market through
the public API. They no longer wait indefinitely after falling outside the most
recent 50 events. Existing identity and final-result checks remain authoritative;
an unavailable or unrelated response leaves the Call pending.

The UP Call for September 27 at 11:15 PM New York time, ID 1790565588458,
was reconciled through the existing ledger path against finalized market
KXBTC15M-26SEP272330-30 (strike 83429.03, close 03:30 UTC September 28).
Its official outcome is DOWN and its Call result is LOSS. Original decision
evidence is unchanged; a settlement revision records null → LOSS.

Validation: regression tests cover history validity, actual observation coverage,
feed interruption/recovery, source/asset switching, deadline behavior, blocker
persistence and exact-market settlement. An isolated local browser with Supabase
and Discord requests blocked progressed from DATA WAIT to DATA READY and formed
a qualified Call before the cutoff. No real order was placed by testing.

Rollback trigger: runtime errors, fresh continuous inputs unable to become ready,
blocker evidence missing from a new sit-out, or official settlement identity
checks failing. Revert this release's code commit if required; preserve the
verified historical settlement and its revision.
