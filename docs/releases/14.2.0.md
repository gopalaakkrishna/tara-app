# TARA 14.2.0 — call integrity and early-lock research

## Live fixes

- The late-force path captures a fresh, matching Kalshi quote before price validation. A missing quote can recover until the existing 30-second deadline; after that, missing data remains a sit-out. The validated decision is logged before it is persisted.
- New call snapshots retain original direction, time, strike, market identity, quote, raw forecast, score, version, and reason. Record updates preserve that original and retain a correction trail.
- The record excludes non-directional rows and explicit contract-identity quarantines. Twenty-one malformed historical SIT_OUT/LOSS rows are repaired to SITOUT without discarding the original.
- Five historical results with matching at-lock strike and window are corrected against the September 27 public Kalshi audit. Two wrong-strike cases are preserved and marked for review, not guessed. New explicit user edits are distinguishable from stale cloud restores.
- Future automatic settlement reconciliation requires matching ticker (or matching legacy strike), asset, close time and settled exchange status. Non-directional entries cannot become losses merely because they differ from UP/DOWN.
- AutoTrade entry validates fresh quotes against the current window and the locked ticker. Stake settings, cooldown, entry band, exits and order/fill reconciliation are unchanged.

## Shadow research — not live strategy

Analytics now includes Decision Quality. `early-7m-v1` observes BTC 15-minute windows every 15 seconds. Its candidate requires 30 seconds of continuous qualifying observations, a raw side estimate of at least 65%, and at least 3 cents estimated edge after the default taker-fee model. It may not lock after seven minutes remaining.

These thresholds are deliberately labeled **uncalibrated research parameters**, not proven winning thresholds. The research module has no order, arm, or live-lock callback. There is no automatic promotion switch. The existing live engine's timing policy remains in place except for the missing-quote correctness fix.

The comparison contains the first observed current Tara lock, the early candidate, and the market favorite at the candidate's timestamp. It measures participation, W/L, probability calibration/Brier error and estimated quote-to-settlement return. A same-time market baseline is not an unconditional buy-the-favorite strategy. Price estimates are not fills or actual account P&L.

Only officially settled, sufficiently observed windows enter the comparison. Opening after the first 30 seconds or an observation gap over 45 seconds through the close makes a window partial. This includes the period after the early cutoff, so a late current-policy lock cannot be missed and called a sit-out. Browser downtime is not invented as a sit-out. Data is stored in a separate IndexedDB database, with per-window/device cloud research backups and JSON export. One tab per origin is the writer; other tabs are viewers. This is **not an always-on server engine** and closing all Tara tabs stops observation. Cloud backup is not an automatic recovery/import facility in this release.

Calibration uses only previous complete windows whose outcomes were verified before the estimate time. It needs at least 30 comparable samples to display an empirical bin estimate. That estimate does not change live confidence or execution.

## Promotion criteria and remaining work

This release implements the correctness and measurement phase. It does not establish that earlier locking wins more. Collect a chronological forward sample before considering a strategy change. A first checkpoint is 300 complete windows across multiple days, not proof by itself.

Compare the same eligible windows and require acceptable participation, improved probability calibration, and improved net returns with executable prices, realistic fill/slippage costs and drawdown limits. Evaluate parameter changes on training data, freeze a new protocol version, then measure an untouched forward sample. Do not use post-lock reversals or a window's later peak confidence to select an earlier call. Keep hourly evaluation separate.

Replacing the live browser-coordinated engine with an always-on authoritative server, introducing a new settlement-index forecast model, and activating the early candidate are future stages—not changes silently included in this release. Actual exchange positions/fills still require successful authenticated reconciliation; no money was moved to test this release.

## Verification and rollback

- `npm test`: pure lifecycle, quote validation, history integrity, settlement, calibration, partial-window, direction/price and existing hourly/position tests.
- `npm run build` runs the regression tests before compiling, including on Cloudflare, so a failed test blocks the build. Also run `git diff --check`.
- Isolated browser checks block external writes and use no Kalshi credentials. Confirm overview, Analytics, mobile overflow, export, reload persistence, and unchanged navigation. Third-party TradingView metainfo errors are reported separately from application exceptions.
- Production delivery uses the existing GitHub → Cloudflare Pages integration. Verify the deployed commit and the V14.2.0 bundle before calling it live.
- Rollback the release commit through the same deployment route if needed. Research is isolated from orders. Historical originals and revision evidence remain saved; do not erase data to roll back code.
