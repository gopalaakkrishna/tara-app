# 14.4.4 — Fresh candle requests and visible Memory blockers

Includes the startup readiness, blocker evidence and captured-market settlement
repairs from 14.4.3. The production smoke check caught a further input issue:
the no-range Coinbase candle URL returned one-minute candles several minutes
old despite a fresh fetch receipt. Readiness correctly reported the stale bars.

Coinbase candle requests now specify both start and end, within its documented
300-candle limit. The range advances every 30 seconds so the previous cached
response cannot keep masquerading as current history. Poll frequency is unchanged.
A direct public-API check returned 299 candles with the latest bar in the current
minute. Other providers' endpoint contracts are unchanged.

The full Memory list also displays the captured blocker reason for new blocked
decisions, alongside the existing confidence, regime and quality fields. Original
older decisions are not retroactively assigned new blocker explanations.

Validation: supported request ranges, refresh-key advancement and invalid inputs
are tested along with the readiness, deadline, persistence and settlement tests.
The completed release is checked in an isolated production browser with shared
cloud writes and outbound notifications blocked. The corrected historical Call
is separately verified in the user's live Memory and shared cloud ledger.
