# 14.4.5 — Reliable cloud finalization and exact Call blockers

The October 12 three-window watch reproduced two defects: pending→SITOUT
finalization was skipped by a coarse cloud signature until a new window logged,
and the deadline recorded "forming" rather than the actual timing hold.

## Repairs

- The cloud pre-gate compares canonical, actually published record content,
  including results, blockers, original evidence and corrections. Equivalent key
  ordering does not trigger another write. Unchanged records still skip the large
  read/write. Successful insert/update acknowledges only the payload actually
  attempted, not another concurrent pending signature; failed writes remain
  retryable. Existing optimistic concurrency and history protections remain.
- A queued Call-log flush keeps its original 60-second deadline and reads the
  latest pending payload; ongoing changes cannot indefinitely restart it. Other
  cloud paths retain their existing debounce behavior. The cloud record cap stays
  1,000. Peer status and catch-up merge now recognize sit-out finalization and
  same-window evidence updates, preserving the existing catch-up cooldown.
- Actual timing-confidence, timing-price, adverse-Kalshi abort/cooldown, rollover
  grace, shared-lock restore and final commit rejections stamp their exact hold.
  Blocker evidence includes observed confidence, required confidence, effective
  directional-price ceiling, remaining time and cooldown counts when applicable.
  It goes to the live Call, deadline snapshot, original decision, Memory and shared
  caches. Old-window/asset/future/stale holds cannot explain the current window.
  A candidate direction change labels the previous evaluated gate explicitly;
  released timing waits are cleared rather than shown as still active.

No lock thresholds, confidence bands, quote gates, cutoff, sample rules,
AutoTrade settings, feature flags or execution pause were changed. No old
decision is given a fabricated retrospective blocker. This release fixes
observability and persistence, not win rates or the number of qualifying Calls.

## Verification and rollback

Regression tests exercise the actual application's cloud writer, merge,
timing-controller and cooldown branches with isolated fake clients/refs/clocks.
Cases include same-id pending→SITOUT without a new window, blocker-only changes,
unchanged-write suppression, failed reads/writes, inserts/conflicts, rapid-update
flush liveness, hundreds of samples under a confidence hold, valid direction
changes, stale identities, release of a hold, and original/cached deadline evidence.

Run the complete test suite and production build before push. Verify Cloudflare's
new asset/version after deployment. Smoke tests must not create a second active
trading engine, write fake records to production or activate AutoTrade. Existing
live tabs need one refresh to load the update; the monitor remains paused.

Local validation: 117 tests pass, including 23 added regression cases. An isolated
browser check executed the real cloud writer with fake clients and confirmed
same-window SITOUT finalization, unchanged-write suppression, preserved original
evidence, and a 58%/65% timing blocker despite 405.9 samples. No production records
were used. The temporary QA page/server/tab were removed. Source comparisons
confirmed that the commit policy (apart from version), persistence guard, decision
threshold expressions, execution-integrity module and execution pause are intact.

Rollback: revert this release commit if the cloud writer throws/repeatedly writes
unchanged evidence, captured Calls mutate or the display crashes. Keep the live
entry pause and decision thresholds untouched during rollback. There is no
database schema migration or new secret/permission.
