# 14.4.10 — hourly fresh confirmations and pick approval

Hourly confirmations previously advanced on every React render. Weak forming
signals could lock without a confidence check or any comparison of the hourly
probability to the executable price. Price alone ranked the candidates. A
proposed lock also appeared in the UI before the record could refuse it.

## Behavior

Count a confirmation only when a successful hourly market poll and a spot
observation both advance. The same event, close, contract, direction and source
must keep qualifying. Default three confirmations span at least40s across the
existing20s polling cadence. Existing doubled confirmation for a reversal remains.
Repeated renders, reused quotes and a timer alone cannot add evidence. Weak
signals, failed/stale feeds, long observation gaps and changed identity reset it.

Apply the existing65-point signal confidence standard to hourly admission. This
is newly enforced for hourly; no15m confidence rule changes. Require the hourly
barrier model to support the chosen side (>50%) and exceed its executable cost
plus the estimated one-contract taker fee. Convert model P(YES) to P(NO) for NO;
do not confuse signal score with calibrated probability. Rank qualifying strikes
by estimated net edge. Skip duplicate/conflicting strikes before selecting.
These are admission consistency checks; the historical model is unchanged and
its edge remains an estimate, not a demonstrated profitable strategy.

Poll receipt and request times, event/ticker/close, market status and strike type
are validated. Failed requests retain old rows for reference but block approval.
Overlapping pulls cannot deliver out-of-order replacements. Spot must be within
15s and quote request within45s. Fetch current KXBTCD fee type/multiplier (cached
one hour); unavailable/unsupported fees block with an explicit reason. Official
public Kalshi bases replace the third-party CORS fallback. No new authentication
or account/order request is involved.

Only a locally persisted, accepted pick appears LOCKED or triggers its existing
alert. Strict shared-record read failure shows a hold. Revalidate current
candidate, timing, quote, confidence, edge and confirmation requirement after
that asynchronous read, including a remote lock that raises flip confirmation.
Then recheck merged duplicates, contradictions, cap and cooldown. Persist the
original observation time, structured approval and sample evidence. Refresh
preserves cooldown and capture; it cannot manufacture new confirmation history.
Settlement merges the latest local record so its older read cannot erase a pick
accepted while it awaited a result. Equal record counts no longer suppress a
cloud hydration that contains changed approval evidence or outcomes.

Panel displays the actual hourly blocker/confirmation status, labels model YES
on the ladder and model probability for the chosen side on locks, and shows
captured sample count/estimated net edge. Historical accuracy bands are labelled
historical; newly captured picks do not carry a fixed accuracy claim.

## Preserved

The15m420s cutoff, all15m confidence/tier/sample/price/gap/cooldown rules and
AutoTrade settings, entry/exit/order logic and execution pause remain unchanged.
Hourly existing defaults and overrides remain:3 confirmations,45–60c cost band,
3 locks,3min cooldown,40min maximum time left and0–15min dead zone. Original
hourly probability function and calibration constants are unchanged. No user
settings, production record edits, data migrations or order calls are part of
validation. A shared hourly document read remains advisory conflict detection;
this release does not establish a server-atomic cross-device reservation.

## Verification and rollback

Tests exercise the production hourly component effects, actual polling and
record hooks, real probability function and isolated clocks/storage/fetches.
Cover UP/YES and DOWN/NO, repeated renders, fresh sample timing, stale/failed
inputs, resets, model/fee/price symmetry, threshold boundaries, candidate ranking,
overrides, scope, pending/history guards, refresh, shared conflicts, duplicate
panels, quota failure, in-flight direction/time changes, delayed settlement and
approval evidence preservation. Three previously captured loss inputs are
regression fixtures; their results are not input to approval or a profitability
backtest. Run the full suite and production build before release.

Verify deployed commit, Cloudflare status and served asset version. User controls
refresh of an existing trading tab; live runtime after loading the new release
is distinct from build verification. Revert this release if confirmations advance
without fresh inputs, phantom locks/duplicate alerts appear, capture changes,
valid markets cannot load, or the record loses pending/settled entries. Preserve
the live-execution pause through rollback.
